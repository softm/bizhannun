# 사업자한눈: 정보 연결과 사업자 인사이트

기준일: 2026-10-21  
대상: 사업자 조회, 거래처 목록·상세, 상태 확인 흐름

## 1. 해결할 문제

사업자번호 조회 화면에 공개 상호가 표시돼도 저장한 거래처 이름이 비어 있으면 목록과 상세에서 `이름 미입력`으로 보였다. 국세청 상태 조회와 공개 업체정보 수집, 개인 거래처 저장이 서로 다른 자료인데 화면별로 읽는 값도 달랐기 때문이다.

사업자번호를 단일 연결 기준으로 삼고, 저장한 거래처·조회 응답·공개 수집본을 표시 시점에 결합한다. 정보가 있다는 사실만 나열하지 않고 지금 무엇을 확인해야 하는지 순서를 제공한다.

| 질문 | 제공할 화면 정보 | 연결·판단 기준 |
| --- | --- | --- |
| 이 번호가 어떤 업체인가? | 저장한 별칭, 공개 상호, 주소, 업태·종목, 연락처 | 10자리 사업자번호 일치와 항목별 출처 |
| 확인한 등록 상태는 무엇인가? | 계속·휴업·폐업 상태, 과세유형, 정상 조회시각 | 같은 번호의 정상 조회 응답 |
| 정보가 서로 맞는가? | 출처별 값 차이, 각각의 수집시각 | 같은 사업자로 연결된 자료의 동일 항목 비교 |
| 얼마나 확인했고 무엇이 비어 있는가? | 기본정보 6개 중 확인된 항목 수와 미확보 항목 | 출처가 연결된 상호·주소·전화·업태·종목·웹사이트 |
| 지금 무엇을 하면 되는가? | 상태 재확인, 등록정보 대조, 출처 차이 확인, 자료 보강 | 실패·시점·충돌·누락에 따른 명시적 우선순위 |
| 이전과 달라졌는가? | 최근 조회 8건과 상태 변화 | 같은 번호·같은 출처의 서로 다른 시점의 정상 조회 비교 |

## 2. 정보 연결 구조

### 기준 식별자

- 사업자번호는 하이픈·공백을 제거한 10자리 문자열로 취급한다.
- 검증번호 검사는 번호 형식 확인이며 실제 등록 확인이 아니다.
- 거래처의 사업자번호, 조회 결과의 사업자번호, 공개 수집본의 사업자번호가 각각 일치해야 사용한다.
- 상호가 비슷하거나 검색어가 같다는 이유로 업체를 연결하지 않는다.
- 원천 자료에서 사업자번호 일치 또는 기존 수집 규칙에 따라 공식 도메인이 확인된 출처만 기본정보에 반영한다.
- 확인 전 검색결과·뉴스·채용·SNS 후보는 후보로 유지한다.

### 저장 정보와 공개 정보

| 정보 | 기준 위치 | 표시 원칙 |
| --- | --- | --- |
| 거래처 사업자번호·별칭·메모·태그 | 기존 개인 작업공간, 로그인 시 계정별 Firestore | 직접 입력한 값을 자동으로 덮어쓰지 않음 |
| 공개 상호·주소·업종·전화 등 | 정규화된 공개 수집본 | 사업자번호로 연결하고 값마다 출처·수집일 유지 |
| 상태·과세유형·조회이력 | 기존 상태 조회 결과와 개인 확인기록 | 최근 조회 실패와 직전 성공 기록을 분리 |
| 인사이트 | 위 자료로 화면에서 계산 | 저장된 자료를 수정하거나 신용등급을 생성하지 않음 |

직접 저장한 이름이 있으면 표시 이름으로 유지하고 공개 상호가 다를 때는 별도 안내한다. 사용자 별칭과 공개 상호가 다른 것 자체를 허위정보나 출처 충돌로 분류하지 않는다. 저장한 이름이 비어 있으면 번호가 일치하는 공개 상호를 사용한다.

공개정보를 개인 거래처에 반복 복사하지 않아도, 저장된 사업자번호가 연결 고리가 되어 같은 자료를 조회·목록·상세에서 사용할 수 있다. 사용자의 메모·태그와 다른 거래처 관계는 공개 수집본에 포함하지 않는다.

## 3. 인사이트 계산 규칙

| 기능 | 입력 | 출력과 동작 |
| --- | --- | --- |
| 등록 상태 | 같은 번호의 최신 조회와 마지막 정상 조회 | 조회 실패 시 `직전 성공 기록`으로 분리하고 다시 확인 버튼 제공 |
| 상태 재확인 | 정상 조회시각 | 7일 초과, 시각 누락, 미래 시각, 최근 조회 실패 시 재확인 안내 |
| 자료 기준일 확인 | 선택된 항목의 실제 원천 수집시각 | 30일 초과 또는 시각 미확인 항목 수 안내 |
| 기본정보 확인 범위 | 상호·주소·전화·업태·종목·웹사이트 | `5 / 6개`처럼 표시하고 미확보 항목을 이름으로 제시 |
| 출처별 값 차이 | 선택된 값과 같은 사업자로 확인된 대체 관측값 | 상호·주소·전화 등 값 차이와 출처별 날짜 표시 |
| 연결 범위 | 검증된 출처 URL·호스트 | URL 중복과 `www` 호스트 중복을 제거해 자료 수·사이트 수 표시 |
| 웹 후보 안내 | 동일 사업자 여부가 확인되지 않은 출처 | 후보 수만 표시하고 기본정보·확인 범위 계산에서는 제외 |
| 상태 변화 | 번호·출처가 같은 정상 조회들 | 실제 상태가 다른 경우에만 변화 표시, 실패를 폐업으로 변환하지 않음 |

**7일·30일은 이 앱의 재확인 안내 기준이다.** 국세청이나 다른 제공기관의 자료 갱신 주기라고 표시하지 않는다. 수집 작업을 오늘 실행했더라도 개별 항목의 기존 출처 수집일을 오늘로 바꾸지 않는다.

출처 사이트 수는 서로 다른 웹 주소를 구분한 수치다. 여러 사이트가 같은 원천을 재인용할 수 있으므로 독립 검증 횟수로 해석하지 않는다. 기본정보 확인 수 역시 정보의 확보 범위이며 신용점수·거래 안전등급·지급능력 점수가 아니다.

### 행동 우선순위

1. 번호 형식 또는 연결 번호 불일치 확인.
2. 최근 조회 실패·자료 없음·연결 설정 대기 재확인.
3. 정상 조회시각 재확인.
4. 조회된 휴업·폐업 상태와 업무 진행 여부 확인.
5. 출처별 값 차이 확인.
6. 오래되거나 시각이 불명확한 공개자료 보강.
7. 수집 일부 실패와 기본정보 누락 확인.
8. 등록증과 거래 서류의 등록정보 대조.
9. 연결 후보 원문 확인.

처음에는 우선순위가 높은 3개 행동을 표시하고 나머지는 펼쳐서 확인한다. 거래처 상세의 간략 모드에서는 우선 2개를 표시한다.

## 4. 등록 상태와 업체 정보의 구분

국세청 상태 조회에서 확인한 상태·과세유형과 웹에서 확인한 상호·주소는 서로 다른 출처의 관측값이다. 공개 상호가 있다는 이유로 국세청이 그 상호를 반환한 것처럼 표시하지 않는다.

등록정보 대조는 사용자가 가진 사업자번호·개업일·대표자 등 입력과 등록정보를 비교하는 절차다. 화면의 상태 조회만으로 그 입력값 전체가 대조됐다고 표시하지 않는다.

관련 공식 자료: [국세청 사업자등록정보 진위확인 및 상태조회 서비스](https://www.data.go.kr/data/15081808/openapi.do).

법인등록번호·DART 고유번호·종목코드는 사업자번호와 다른 식별자다. 향후 해당 자료를 추가할 때는 원천이 제공하는 대응 관계를 확인해서 연결하며 숫자 길이나 이름 유사성만으로 결합하지 않는다.

## 5. 코드 계약

| 파일 | 책임 |
| --- | --- |
| `src/business-profile.mjs` | 정규화된 번호로 개인 거래처와 공개정보를 결합하는 공통 표시 모델 |
| `src/enrichment.mjs` | 공개 수집본·출처·필드 정규화, 연결 상태와 후보 분리 |
| `src/business-insights.mjs` | 상태·자료 기준일·기본정보·출처 차이·행동·타임라인의 순수 계산 |
| `src/business-insights-view.mjs` | HTML 이스케이프와 안전한 URL 처리를 적용한 인사이트 화면 |
| `src/app.mjs` | 조회·저장·목록·상세 및 행동 버튼 연결 |
| `tests/business-insights.test.mjs` | 번호 오결합·실패·후보·시각·출처 차이·화면 출력 회귀 검증 |

인사이트 입력:

`buildBusinessInsights({businessNumber, partner, check, summary, now})`

주요 출력:

- `status.needsRefresh`: 정상 결과 부재·최근 실패·시각 문제·7일 초과.
- `profile.confirmedCount`, `profile.totalCount`, `profile.missing`: 기본정보 범위.
- `evidence.sourceCount`, `domainCount`, `candidateCount`: 연결 출처와 후보.
- `conflicts`: 출처별 값 차이 목록.
- `actions`: 버튼 동작과 우선순위를 포함한 행동 목록.
- `timeline`: 최근 조회 8건, 같은 출처의 정상 조회 사이의 변화.

렌더링:

`renderBusinessInsights(model, {compact: false})`

행동 버튼은 `data-bno`에 대상 사업자번호를 포함한다. `insight-refresh-status`, `validate-registration`, `insight-view-sources`, `enrichment-request` 동작으로 이어진다.

## 6. 확인해야 할 사용 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| 저장한 이름은 비어 있고 공개 상호는 확보됨 | 동일 번호의 상호로 조회·목록·상세 표시 연결 |
| 저장한 별칭과 공개 상호가 다름 | 별칭 보존, 공개 상호 별도 안내, 자동 덮어쓰기 없음 |
| 다른 업체의 응답이 뒤늦게 도착함 | 번호가 다른 응답은 연결·인사이트에서 제외 |
| 같은 이름의 검색결과만 있음 | 후보 표시, 기본정보 확인 수에 포함하지 않음 |
| 최신 조회 실패, 이전 정상 기록 있음 | 현재 확인 실패와 직전 성공 상태·시각을 동시에 표시 |
| 공개 자료 수집 일부 실패 | 확보된 이전 자료와 실제 출처 수집일 유지 |
| 주소가 두 출처에서 다름 | 양쪽 주소와 출처·수집일 표시, 오류 원인을 단정하지 않음 |
| 자료가 전혀 없음 | 미확인·미확보 표시와 실제 수행 가능한 확인 버튼 제공 |
| 출처 URL이 스크립트·인증정보·비공개 주소를 포함 | 링크로 렌더링하지 않음 |
| 사용자가 저장한 이름·자료 값에 HTML이 포함됨 | 텍스트로 표시하고 실행하지 않음 |

배포 성공 여부와 실제 브라우저 검증 기록은 이 기획 문서와 별도로 운영 검증 기록에서 확인한다.
