# 사업자한눈 공개정보 수집·연결·인사이트 — v0.4

기준일: 2026-10-21, 한국 시간. GitHub Actions가 명시적으로 등록한 사업자의 공개 웹·등록자료를 수집하고 GitHub Pages가 출처가 붙은 결과를 제공합니다. 국세청 상태조회와 Firebase 인증·Firestore 저장은 기존 직접 연결을 유지합니다. Vercel은 사용하지 않습니다.

[서비스](https://softm.github.io/bizhannun/) · [데이터 현황](https://softm.github.io/bizhannun/data-status.html) · [수집 실행 기록](https://github.com/softm/bizhannun/actions/workflows/pages.yml) · [공개 수집 JSON](https://softm.github.io/bizhannun/data/enrichment/index.json)

## 조회부터 저장까지

| 동작 | 실제 동작과 보존 범위 |
| --- | --- |
| 사업자 조회 | 정규화한 사업자번호로 국세청 조회, 공개 수집본, 같은 번호의 저장 거래처를 연결합니다. 같은 상호만으로 다른 사업자의 정보를 합치지 않습니다. |
| 거래처 저장·공개정보 저장 | 출처·항목·수집일·동일성·수집 상태를 `partner.enrichment`에 구조적으로 보관합니다. 사용자 메모나 태그와 분리하며 메모 끝에 자료를 덧붙이지 않습니다. |
| 거래처 목록·상세 | 저장된 공개정보와 배포된 최신 수집본을 같은 번호로 연결해 상호·주소·업종·출처를 표시합니다. 새 수집본이 없거나 일부 조회가 실패해도 기존 근거를 사용할 수 있습니다. |
| 내 사업으로 입력 | 같은 사업자의 사용자 입력과 작성 중인 초안을 보존하고, 확인된 상호·업종·주소의 지역·정확한 설립일로 빈칸만 채운 검토용 초안을 엽니다. 저장 시 `profile.enrichment`에 공개 근거를 별도로 보관합니다. |
| 자료 새로고침 | 이미 배포된 수집 JSON을 다시 불러옵니다. 버튼만으로 웹 수집을 즉시 실행하지는 않습니다. |
| 웹 정보 수집 요청 | 공개 요청 작성 화면이나 Actions 수동 실행을 통해 공개 수집 대상을 명시적으로 추가합니다. |
| 다운로드·백업 | 공개 수집 JSON과 계정/기기 작업공간 백업에서 구조화된 근거를 보존합니다. 사용자 메모는 공개 수집 JSON에 포함하지 않습니다. |

빈 거래처 이름에는 확인된 공개 상호를 표시하고, 저장한 자동 이름은 이후 확인된 상호로 갱신할 수 있습니다. 사용자가 입력한 이름이나 별칭은 유지하며 공개 상호와 출처를 함께 보여 줍니다. 이름 출처 정보가 없는 기존의 비어 있지 않은 이름도 사용자 입력으로 취급합니다. 다른 사업자번호의 근거를 거래처나 내 사업 프로필에 저장하는 것은 거부합니다.

내 사업의 기존 매출·인원·설립일·업종·지역 등 수동 입력을 공개자료로 덮어쓰지 않습니다. 번호를 바꾸면 이전 업체의 근거와 사업 수치를 새 업체로 옮기지 않습니다. 고용·산재보험 성립일을 설립일로, 보험 적용 인원을 회사 전체 직원수로 바꾸지 않습니다.

## 확보 범위와 인사이트

화면의 기본항목 체크리스트는 **상호·주소·전화·업태·종목·웹사이트 6개**입니다. 같은 번호에 연결된 출처의 실제 항목을 기준으로 확보 범위를 표시하며, 확정되지 않은 검색 후보는 이 수에 넣지 않습니다.

| 점검 | 근거와 해석 |
| --- | --- |
| 확보·누락 항목 | 동일 사업자로 확인된 출처의 항목만 셉니다. 자료가 없으면 아직 연결하지 못한 항목으로 안내하며 영업 상태나 신용을 추정하지 않습니다. |
| 출처별 차이 | 같은 항목의 서로 다른 값과 각각의 원문·수집일을 함께 보관합니다. 사용자 별칭과 공개 상호의 차이도 사용자 입력을 유지한 상태로 안내합니다. |
| 오래된 자료 | 각 항목을 뒷받침하는 출처의 원래 수집일을 기준으로 공개자료 30일, 상태조회 7일의 재확인 안내를 제공합니다. 이는 앱의 확인 정책이며 기관의 갱신 주기를 뜻하지 않습니다. |
| 저장본과 최신 관측값 차이 | 기존 저장본과 새 수집본에서 모두 확인된 항목의 값이 달라졌을 때 비교합니다. 관측값 차이이며 실제 이전·상호 변경일을 알아낸 것으로 표시하지 않습니다. |
| 후보·연결 철회 | 같은 이름, 관련 링크, 검색 결과만 있는 자료는 후보로 분리합니다. 다른 업체가 섞인 것으로 확인된 자료도 확정 정보에서 제외합니다. |
| 수집 미완료·상태 이력 | 실패한 조회와 직전 성공 자료를 구분합니다. 같은 출처에서 확인한 상태 이력의 차이는 조회 시점과 함께 표시합니다. |

기사·검색 결과·리뷰의 수나 어조로 신용점수 또는 거래 안전성 점수를 만들지 않습니다. 조회 결과 없음, 인증키 미설정, 접근 제한, 통신 실패는 폐업과 별개의 결과입니다.

## 채널별 연결 범위

어댑터가 구현되어 있다는 것과 운영 키 등록·기관 활용승인·실제 응답 성공은 별도입니다. 아래 선택형 API는 필요한 키가 있을 때 실행하며, 키가 없거나 승인되지 않으면 출처별 상태에 그 사유를 남깁니다. 수집 성공 여부는 실행 기록과 각 출처의 결과로 확인합니다.

외부 사이트로 이동하는 검색 버튼은 수집된 자료와 구분합니다. 검색 링크를 만들었다는 이유로 해당 사이트를 읽었거나 자료를 확보했다고 표시하지 않습니다.

[나라장터 등록업체](https://www.data.go.kr/data/15129466/openapi.do), [국민연금 사업장](https://www.data.go.kr/data/3046071/openapi.do), 업종별 인허가·면허, 인증·특허, 공시·재무제표 전체 연결은 후속 범위이며 현재 구현된 수집 채널에 포함하지 않습니다. 국민연금 가입인원·고지액으로 전체 직원수나 실제 연봉을 추정하는 기능도 없습니다.

## 동일 사업자 연결과 잘못된 근거의 철회

| 연결 표시 | 채택 조건 |
| --- | --- |
| `exact_bno` | 해당 사실이 귀속되는 업체의 사업자번호가 조회 번호와 정확히 일치합니다. |
| `confirmed_domain` | 검토된 공식 도메인에 있는 해당 업체 자체의 정보입니다. 제안된 URL이라는 이유만으로 공식 도메인이 되지는 않습니다. |
| `candidate` | 같은 이름, 검색 결과, 관련 링크 등 추가 대조가 필요한 자료입니다. 확정 개요와 확보 항목 계산에 합치지 않습니다. |

페이지 어딘가에 번호가 있다는 사실만으로 전체 내용을 해당 업체의 정보로 연결하지 않습니다. 디렉터리 운영사 푸터, 관계사 소개, 여러 업체가 섞인 표, 숨겨진 영역과 대상 업체의 내용을 구분합니다. 공식 도메인 안에서도 관계사 자료를 모회사 자체 정보로 합치지 않습니다.

출처와 그 출처의 필드는 하나의 관측 묶음으로 보관합니다. 같은 페이지의 새 수집은 같은 출처의 이전 관측과 비교하며, 서로 다른 등록자료와 검토된 과거 관측은 독립 근거로 보존합니다. 과거 값을 새 수집일에 읽은 것처럼 날짜만 바꾸지 않습니다.

| 새 수집 결과 | 저장된 근거 처리 |
| --- | --- |
| HTTP·robots 오류, 접근 제한, 빈 결과, 번호 확인 불가 | 이전 확인값과 원래 수집일을 유지하고 이번 실패 시각·사유를 별도로 기록합니다. |
| 다른 사업자번호 또는 다른 업체의 내용임이 명시적으로 확인됨 | 해당 URL에 `identity_mismatch` / `entity_scope_mismatch`를 기록하고 그 시점 이전의 동일 URL 근거를 후보로 낮춥니다. 과거 검토 근거도 이 철회의 대상입니다. |
| 철회 후 과거 수집본을 다시 불러옴 | 과거의 확정 표시만으로 철회된 연결을 복구하지 않습니다. |
| 철회 시각 이후 해당 업체임을 새로 확인함 | 새 근거와 수집일에 따라 다시 연결할 수 있습니다. |

철회된 출처에만 의존하던 자동 이름은 확정 이름으로 남기지 않습니다. 원래 값은 후보 근거로 남고, 사용자가 직접 입력한 이름은 유지합니다.

## 공개 수집 대상 추가와 설정

앱의 `웹 정보 수집 요청`에서 공개 상호·웹사이트를 입력하고 `공개 요청 작성 화면 열기`로 이동해 내용을 확인한 뒤 제출합니다. 사업자번호·상호·웹사이트가 공개 요청에 기록됩니다. 내부 메모나 비공개 연락처를 넣지 않습니다.

저장소 소유자·협업자·조직 구성원의 `[사업자 수집]` 요청은 자동 실행합니다. 일반 외부인의 요청은 운영자가 검토한 뒤 Actions 수동 실행으로 처리합니다. 요청 내용을 shell 명령으로 실행하지 않습니다.

[Actions 수동 실행](https://github.com/softm/bizhannun/actions/workflows/pages.yml)은 `business_number`, `company_name`, `website`를 받습니다. 번호를 비우면 등록된 전체 대상을 갱신합니다. 기존 번호를 웹사이트 없이 다시 요청하면 검토된 기존 시작 URL을 보존합니다. 새 대상에 URL이 없으면 사업자 디렉터리의 해당 번호 페이지를 시작점으로 시도합니다.

`config/business-sources.json`은 공개 수집 대상으로 명시한 사업자 목록이며 개인 Firestore 거래처를 자동으로 공개하는 대기열이 아닙니다.

| 설정 | 의미 |
| --- | --- |
| `businessNumber` | 검증된 10자리 사업자번호 |
| `name` | 공개 상호·검색 힌트. 입력만으로 검증된 법적 명칭이 되지 않습니다. |
| `website` | 수집 시작 URL |
| `sourceUrls` | 함께 시도할 추가 공개 URL. 최대 6개를 등록할 수 있습니다. |
| `channel` | 홈페이지·민간 디렉터리 등 출처의 종류 |
| `verifiedDomain` | 검토를 거쳐 확인한 공식 도메인 여부. 새 URL 제안은 자동 승인하지 않습니다. |
| `search` | 허용되는 검색 RSS를 통한 후보 발견 여부 |
| `corporateNumber` | 금융위 조회에 사용할 13자리 법인등록번호. 없으면 공개 상호로 조회하고 응답의 사업자번호를 대조합니다. |
| `corpCode` 또는 `dartCorpCode` | OpenDART 조회에 사용할 8자리 기업 고유번호. 없으면 같은 실행의 번호 일치 금융위 응답에서 연결할 수 있습니다. |

설정 대상은 최대 100개이며, 한 사업자의 웹 수집은 시작 URL·추가 URL·발견한 회사소개 및 연락처 페이지를 합해 실행당 최대 4페이지입니다. 추가 URL 6개를 설정해도 모두를 매번 읽는다는 뜻은 아닙니다. 웹 요청은 robots, URL·DNS·리디렉션 검사, 응답 크기 제한과 문자 인코딩 처리를 거칩니다. 로그인·접근 제한·유료벽을 우회하지 않습니다.

## 일정·수집 시각·출처별 상태

자동 일정은 **매일 오전 06:17 한국 시간**입니다. Actions cron은 UTC `17 21 * * *`이며 실제 실행 시각은 실행 기록을 기준으로 확인합니다. main 변경, 수동 실행, 허용된 공개 수집 요청도 실행 계기입니다.

| 저장 필드 | 의미 |
| --- | --- |
| `meta.generatedAt` | 공개 수집 파일을 생성한 시각. 모든 항목을 이때 새로 확인했다는 의미가 아닙니다. |
| `meta.lastAttemptAt`, `collection.lastAttemptAt` | 전체 또는 해당 사업자의 마지막 수집 시도 |
| `meta.lastSuccessAt`, `collection.lastSuccessAt` | 마지막 성공 기록. 개별 사실의 최신성은 해당 출처 시각으로 확인합니다. |
| `meta.schedule` | 표시용 일정, cron, UTC 및 Asia/Seoul 시간대 |
| `sources[].collectedAt` | 해당 출처에서 관측한 시각. 실패한 재실행으로 갱신하지 않습니다. |
| `sources[].publishedAt` | 원문이 제공한 게시 시각. 수집 시각과 구분합니다. |
| `collection.sourceStatuses[]` | 제공자·대상 URL·확인 시각·성공/부분 성공/미설정/자료 없음/번호 불일치/오류, 페이지 수·응답 수·연결 수·전체 수·잘림 여부·사유 |

수집 현황은 자동 주기, 마지막 실행, 확보된 출처의 최근 성공 시각과 채널별 결과를 보여 줍니다. 키 미설정과 해당 출처의 자료 없음도 숨기지 않습니다. 전체 출처 관측 수와 사업자별 중복 제거된 확인 항목 수는 서로 다른 집계입니다. 이 수치는 등록된 공개 수집 대상의 범위이며 전국 모든 사업자를 확보한 수가 아닙니다.

## 선택형 환경변수와 저장 경계

| 환경변수 | 용도·조건 |
| --- | --- |
| `NTS_SERVICE_KEY` | 기존 국세청 브라우저 직접 조회용. 사용자가 선택한 기존 방식에 따라 배포 파일에 포함됩니다. |
| `BUSINESS_PUBLIC_SERVICE_KEY` | 근로복지공단 수집용. 미등록이면 기존 `NTS_SERVICE_KEY`를 시도하지만 해당 API의 별도 활용승인이 필요합니다. |
| `FTC_SERVICE_KEY` | 공정위 통신판매 수집용 |
| `FSC_SERVICE_KEY` | 금융위 기업기본 수집용. 미등록이면 `BUSINESS_PUBLIC_SERVICE_KEY`, 이어서 `NTS_SERVICE_KEY`를 시도하며 서비스 승인은 별도입니다. |
| `DART_API_KEY` | OpenDART 기업개황 수집용 |
| `NAVER_SEARCH_CLIENT_ID` | 네이버 검색 API 애플리케이션 ID |
| `NAVER_SEARCH_CLIENT_SECRET` | 네이버 검색 API 인증값. ID와 함께 필요합니다. |
| `KAKAO_REST_API_KEY` | 카카오 로컬 검색용 REST API 키 |

선택형 채널의 인증값은 Actions에서만 사용하며 공개 수집 JSON이나 브라우저 번들에 넣지 않습니다. 이 표는 필요한 설정명이며 실제 저장소의 키 등록·승인 완료 목록이 아닙니다. Firebase Admin 개인키나 SNS 인증값도 정적 파일에 포함하지 않습니다.

공개 파일 `data/enrichment/index.json`에는 업무상 공개 사실·출처·시각·수집 상태를 저장합니다. 개인 메모·태그·내 사업의 수동 입력은 기존 계정/기기 작업공간에 남습니다. `partner.enrichment`와 `profile.enrichment`는 해당 작업공간에 선택해 보관한 공개 근거이며 Firestore 왕복·백업 복원에서 유지합니다. 기존 작업공간 JSON 분할 저장 구조와 호환합니다.

## 검증 범위

번호 불일치 거부, 후보와 확정 근거 분리, 수동 이름·입력 보존, 자동 이름 갱신, 저장 후 재열기·새 수집본 연결, 근거의 원래 시각 유지, 동일성 철회, 출처별 충돌, 관측값 차이, 내 사업 초안, Firestore 왕복을 회귀 검사합니다. 수집기는 HTML·robots·URL/DNS/리디렉션·응답 제한·인코딩·기관 응답의 번호 일치·페이지·부분 실패를 검사합니다.

로컬 회귀 검사, 외부 API의 실제 응답, Actions 수집 성공, Pages 배포 성공은 각각 별도의 확인 항목입니다. 키가 없는 채널이나 수집하지 않은 기업까지 성공으로 간주하지 않습니다.
