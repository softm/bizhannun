## 이전 설계 기록 — v0.5

기준일: 2026-10-22 한국 시간. 아래 내용은 당시 화면과 검증 기준을 보존한 기록입니다.

범위: 사업자 조회 화면의 정보구조, 상태 전환, 표시 문구와 검수 기준

이 문서는 합의한 설계와 구현 기준을 기록한다. v0.5에 반영한 결과와 실제 브라우저 검증은 [검증 기록](VERIFICATION.md)을 참고한다. 저장·조회·동기화 정책과 사업자번호를 기준으로 한 정보 연결 규칙은 기존 정책을 유지한다.

## 1. 해결할 문제

기존 조회 화면은 검색, 이름 후보, 국세청 결과, 인사이트, 통합정보, 전체 거래처 점검, 거래처 목록, 가이드와 홍보를 연이어 배치한다. 선택한 업체의 이름·상태·기본정보가 반복되고, 한 업체에 대한 행동과 전체 거래처 관리 행동의 범위가 섞인다.

화면의 중심을 **검색 → 후보 선택 → 업체 상세**로 정리한다. 이름 검색은 후보를 고르는 단계이며, 선택한 사업자번호로 상태와 공개자료를 연결한다. 번호 직접 조회는 후보 단계 없이 상세로 이동한다.

## 2. 최종 정보구조

### 검색 작업 영역

- 제목은 `사업자 조회`, 입력은 상호·업체명 또는 사업자등록번호를 받는다.
- `이름·번호 자동 구분`, `상호·업체명`, `사업자등록번호` 검색 기준과 기존 입력 검증을 유지한다.
- 큰 홍보 문구와 장식 대신 검색 입력, 검색 버튼, 한 줄 안내를 우선한다.
- 초기 보조 목록은 `저장한 거래처` 최대 3곳으로 제한한다. 조회 시각에 근거한 목록이 아니므로 `최근`이라고 부르지 않는다.
- 이름 후보는 이름·번호·제공된 주소 또는 업종·출처를 비교할 수 있게 표시한다. 결과가 한 곳이어도 명시적으로 선택한다.
- 후보 선택 후 목록은 `“검색어” 검색 결과 N곳 · 결과 다시 보기` 경로줄로 접는다. 돌아갈 때 검색어·페이지·선택 표시를 유지한다.

### 단일 업체 상세

업체 헤더는 표시 이름, 사업자번호, 필요한 경우 별도의 공개 상호, 이름의 출처·수집 시각, 등록 상태, 저장·수정 및 다시 조회 동작을 담당한다. 같은 이름과 상태를 다른 대형 카드에서 반복하지 않는다.

| 탭 | 코드 값 | 내용 |
| --- | --- | --- |
| 요약 | `overview` | 국세청 핵심 결과와 조회 시각, 기본정보 확인 범위 한 줄, 우선 확인 사항 최대 2개, 등록정보 진위 대조 |
| 사업자 정보 | `facts` | 상호·주소·전화·업태·종목·웹사이트 6개 기본 항목과 추가 공개정보, 각 값의 출처·수집 시각과 다른 출처의 기록 |
| 출처·수집 | `sources` | 연결된 자료, 확인 전 후보, 수집 상태·요청, 외부 탐색 링크, JSON |
| 조회 이력 | `history` | 해당 번호의 조회 기록, 같은 출처의 정상 조회 간 상태 변화, 조회 실패 구분 |

`사업자 정보`는 미확보 기본 항목도 항목명과 `자료 미확보`를 표시한다. 요약의 `기본정보 2/6 · 미확보 4항목` 같은 범위 링크는 이 탭으로 연결한다. 예시 숫자는 실제 모델 값으로 대체한다.

우선 확인 사항은 기존 인사이트의 근거와 순서를 사용한다. 실제 조회 실패, 시각 재확인, 조회된 상태, 비교 대상 항목의 출처 차이를 간결하게 보여준다. 일반적인 진위 대조는 보조동작으로 두고, 자료 미확보·후보 수는 중립적인 범위 안내로 표시한다. 신용점수나 거래 안전등급을 만들지 않는다.

### 전체 작업공간 기능의 위치

| 기능 | 위치 |
| --- | --- |
| 거래처 점검 지표·전체 목록·일괄 등록·일괄 조회 | 거래처 관리 |
| 내 사업으로 입력 | 업체 선택 후 보조동작; 기존 입력·확인 흐름 유지 |
| 사용 가이드 | 도움말 또는 최초 이용 안내 |
| 지원사업 안내·홍보 | 지원사업 찾기 또는 내 사업 |
| 연동 상태·자료 현황 | 기존 계정·동기화 및 데이터 현황; 실제 오류에서도 관련 화면으로 연결 |

조회 앞단의 `거래처 확인 / 내 사업 확인` 선택은 저장 목적에 따른 보조동작으로 옮긴다. 조회 자체는 하나의 흐름으로 제공한다.

## 3. 상태 전환

| 상태 | 화면과 행동 | 보존·전환 규칙 |
| --- | --- | --- |
| 초기 | 검색 입력과 짧은 안내, 저장한 거래처 최대 3곳 | 빈 통계나 전체 관리 목록을 추가하지 않는다. |
| 검색 중 | 이름 검색은 후보 영역에 진행 상태, 번호 조회는 선택 번호의 상세 영역에 진행 상태 | 입력을 유지하고 중복 요청을 막는다. 불러오는 동안 이미 확보한 저장정보 후보는 이용할 수 있다. 최종 결과 전에 0건으로 단정하지 않는다. |
| 이름 결과 | 검색어·결과 수·검색 범위, 후보 목록과 페이지 이동 | 1개 결과도 선택이 필요하다. 같은 번호의 중복은 합치되 다른 번호의 동명 업체는 구분한다. |
| 업체 선택 | 접힌 결과 경로줄과 한 업체 헤더, 기본 탭 `요약` | 새 업체 선택 시 번호 기준으로 상세를 전환한다. 이전 업체의 값이 새 업체 아래에 남지 않게 한다. 결과로 돌아가면 검색어·페이지·선택을 복원한다. |
| 실패·일부 실패 | 오류가 발생한 검색·국세청·공개자료 영역에 원인과 재시도 표시 | 같은 번호의 이전 정상 자료는 실제 시각과 함께 유지한다. 한 출처 실패 때문에 다른 정상 자료를 지우지 않는다. |

추가 전환 규칙:

- 새 검색을 제출하면 이전 선택과 새 검색의 결과가 섞이지 않게 한다.
- 동일 업체의 재조회는 현재 상세와 탭 맥락을 유지하며 진행 상태를 표시한다.
- 새 업체 선택과 계정 전환 뒤에 도착한 이전 응답은 현재 결과를 덮어쓰지 않는다.
- 탭 이동과 후보 탐색만으로 별칭·메모·태그·내 사업 프로필을 저장하거나 수정하지 않는다.
- 조회에 따른 기존 기록 저장, `lastCheck`와 `lastSuccess` 구분, draft 및 계정별 정책을 변경하지 않는다.

## 4. 문구와 정보 범위

| 상황 | 표시 기준 |
| --- | --- |
| 기본 제목·검색 행동 | `사업자 조회`, `검색하기` |
| 초기 보조 목록 | `저장한 거래처` |
| 이름 후보 행동 | `선택 후 조회`, `결과 다시 보기` |
| 상세 저장 행동 | 미등록: `거래처에 저장`; 등록됨: `거래처 정보 수정` |
| 저장한 별칭과 공개 상호가 다름 | 저장 이름을 유지하고 `공개 상호: …`를 별도 표시; 차이만으로 출처 충돌로 분류하지 않음 |
| 검색 결과 없음 | `현재 수집·저장된 범위에서 일치하는 업체를 찾지 못했습니다.`와 번호 조회 또는 거래처 등록 경로 |
| 공개자료 없음 | `자료 미확보`; 업체가 존재하지 않거나 위험하다는 뜻으로 표현하지 않음 |
| 최신 조회 실패·이전 성공 있음 | 현재 실패 안내와 `직전 성공 기록`, 그 상태·조회 시각을 함께 표시 |
| 출처 간 값 차이 | `출처별 값 차이`; 어느 출처가 오류인지 자동 단정하지 않음 |

검색 범위는 **현재 불러온 공개 수집자료와 내 저장정보**다. 전국 사업자 전체 또는 실시간 웹 전체를 검색한다고 표현하지 않는다. 공개 목록 갱신 실패, 정상적으로 불러온 빈 목록, 이름 결과 없음은 구분한다.

목록 생성 시각, 개별 자료 수집 시각, 국세청 조회 시각을 구분한다. 수집 재시도가 실패했다고 이전 자료의 시각을 오늘로 바꾸지 않는다. 자료 수·사이트 수·후보 수는 같은 모델의 집계값을 사용하고, 사이트 수를 독립 검증 횟수로 표현하지 않는다.

사업자번호가 맞는 자료만 연결한다. 기존 공식 도메인 확인 규칙과 후보 분리 규칙을 유지하며 이름 유사성으로 상태·출처를 결합하지 않는다. 국세청 상태와 공개 상호는 각자의 출처를 표시한다. 외부 탐색 결과도 확인 전 후보로 유지한다.

## 5. 반복정보 제거와 점진적 공개

- 업체명·번호·저장 행동은 단일 헤더에 모은다.
- 등록 상태를 헤더 배지와 요약 문맥에서 전달하되, 같은 내용을 별도 대형 지표 카드로 반복하지 않는다.
- 기본 6항목은 `사업자 정보`에서 한 번 제공하고 요약에서는 확인 범위만 연결한다.
- 전체 출처와 수집 진단은 `출처·수집`에 둔다. 핵심 값의 출처·시각과 현재 판단에 영향을 주는 오류는 요약에서도 확인할 수 있어야 한다.
- 조회 이력은 별도 탭에 모으고 전체 거래처 지표는 상세 아래에 반복하지 않는다.

## 6. 접근성과 모바일 기준

- 검색 입력에는 보이는 이름 또는 명시적 접근성 이름을 제공한다. 오류 안내를 입력과 연결하고 오류 발생 시 수정할 위치를 알린다.
- 진행 상태와 결과 변경은 간결한 상태 메시지로 알린다. 전체 상세를 매번 읽게 하는 과도한 실시간 알림은 피한다.
- 탭은 선택 상태와 연결 패널을 표현한다. 키보드로 탭 이동·선택이 가능하고, 비활성 패널 안의 버튼으로 초점이 이동하지 않게 한다.
- 후보 선택 후 업체 제목, 결과로 돌아온 뒤 목록 제목으로 초점을 연결하고 선택했던 후보 표시를 유지한다. `출처 비교` 등은 대상 탭 선택 → 관련 항목 펼침 → 초점 이동까지 수행한다.
- 색 외에 `미확보`, `확인 전 후보`, `직전 성공 기록` 같은 텍스트로 상태를 구분한다. 버튼·링크의 초점 표시를 유지한다.
- 모바일에서도 `요약 / 사업자 정보 / 출처·수집 / 조회 이력` 네 탭을 같은 순서로 제공한다. 탭과 주요 버튼의 터치 영역은 높이 44px 이상을 목표로 한다.
- 모바일의 상세 항목은 한 열로 배치한다. 고정 높이의 내부 스크롤 대신 페이지 스크롤을 사용하고, 긴 이름·주소·출처 URL은 화면 너비 안에서 줄바꿈한다.
- 360px 화면과 글자 확대 환경에서 탭·번호·저장 행동이 겹치거나 잘리지 않도록 검수한다. 주요 행동을 가로 스크롤 뒤에 숨기지 않는다.

## 7. 성공 검수 항목

아래 항목은 화면 설계의 검수 기준이다. 실제 검사 범위와 결과는 [검증 기록](VERIFICATION.md)에 구분해 기록한다.

- 초기 화면에서 제목·입력·검색 행동이 우선하며 `저장한 거래처`는 최대 3곳이다.
- 이름 후보 1곳도 명시적으로 선택하며, 다른 번호의 동명 업체가 합쳐지지 않는다.
- 후보 선택 후 긴 결과 목록이 경로줄로 접히고 상세는 단일 헤더와 네 탭으로 표시된다.
- `결과 다시 보기`가 검색어·페이지·선택 표시를 복원한다.
- 업체를 바꾸거나 계정을 전환해도 이전 응답이 새 상세를 덮어쓰지 않는다.
- 탭별로 배치한 기본정보·출처·조회 이력이 중복된 대형 카드로 다시 나오지 않는다.
- 요약의 우선 확인 사항은 최대 2개이며 각 행동이 관련 조회 또는 근거로 연결된다.
- 기본 6항목의 미확보 상태와 출처별 값 차이를 확인할 수 있다.
- 검색 범위·0건·조회 실패·수집 실패를 구분하고, 실패 시 이전 정상 자료의 시각을 유지한다.
- 저장한 별칭·메모·태그와 기존 저장·조회·draft 정책이 유지된다.
- 키보드로 검색·후보 선택·탭 이동·결과 복귀가 가능하고 초점이 보인다.
- 모바일과 글자 확대 환경에서 탭·번호·주요 행동을 이용할 수 있다.
